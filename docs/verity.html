What we're building

SD Worx's own problem, solved at the moment it happens

SD Worx wrote the story for us. A consultant has an urgent client question. Search returns three documents: one recently updated, one with no owner, one for another country. A colleague then pastes something different from Teams. The information exists, but the consultant has no confidence in any of it.

Verity fixes this in two places. At the door: a document that clashes with the live one gets flagged before anyone can use it. At the question: the consultant gets one answer, from one document, and can see why it's the right one.

1 · Knowledge space

All company knowledge, grouped by subject. Each subject has one live document per country, with a green, amber or red health dot.

2 · Check on upload

A new document is compared with the live one. Any clash is flagged with a level and a deadline to fix it, and the uploader sees exactly what's wrong.

3 · Ask Verity

A small chat on top of the space. It answers in a line and links to the latest document, showing what changed, when, and by whom.

Why we built it this way

Stop bad knowledge at the door, not after the damage

  • Most tools clean up after the fact. They search everything and hope the AI picks the right document. We check every document on the way in, so the space stays clean.
  • One source per subject removes the doubt. If only one live document exists for "home-office allowance, Belgium", the consultant never has to choose.
  • People trust people. Showing who changed it, what changed and when gives the consultant a reason to trust the answer. "The system says so" is not a reason.
  • Deadlines make ownership real. An SLA level turns "someone should fix this" into "Lies must fix this within 24 hours".
  • It's proven. The engine comes from Postura, our compliance product: read sources, check them with fixed rules, flag issues, sign the evidence. We pointed it at knowledge instead of security settings.

Existing tools

"Doesn't Copilot already do this?" No, and we don't replace it.

Good tools already exist for finding documents and answering from them. None of them checks whether a new document contradicts the one that's already live, per rule and per country, at the moment it's uploaded. That's the gap Verity fills.

ToolWhat it does wellWhat it doesn't do
Microsoft 365 Copilot / SharePointAnswers from files people can access; version history and approval flowsDoesn't notice that two files disagree. An old copy in another folder is just as "true" to it
Glean and other enterprise searchSearches across every app with permissions respectedFinds all the versions, but doesn't decide which one is right or stop a wrong one going in
GuruExperts re-verify knowledge cards on a scheduleChecks on a calendar, not on upload. Doesn't compare rule values between documents or countries
Confluence / Notion (with AI)Easy writing, page history, AI Q&AAnyone can publish a page that contradicts another one. Nobody gets flagged, and there's no deadline to fix it
Formal document control (QMS tools)Strict approval, one controlled versionHeavy and slow. Built for regulated manufacturing, not a consultant's quick Teams note

How we position it: Verity is a trust layer in front of the tools SD Worx already uses. It decides which document is the live one, and only live documents go on to Copilot, search or chat. The same check can run on a SharePoint library or a Confluence space later. For the hackathon, Verity has its own upload so the demo is self-contained.

Many sources, one door

Documents arrive from everywhere: email forwards, Google Drive, SharePoint, Git, Teams, PDFs. Whatever the source, every document goes through the same check before anyone can rely on it. Verity records where it came from, who brought it in, and a fingerprint of its exact content, so any later change is visible.

What makes it hard to copy in a weekend: the check works on the rules inside a document (cap, deadline, payslip code), not on whole-file similarity. It is also country-aware (BE vs NL vs ALL) and ends in a decision by a named owner, with an SLA and an audit trail. The AI only reads and phrases. It never decides what's true.

Security

What we did, in plain words

  • Everyone logs in. Passwords are stored scrambled, never as plain text.
  • Each person only sees documents for their countries. The check runs on the server for every request, so changing a link or an ID doesn't reveal anything. This is exactly what Aikido tests.
  • Only knowledge owners can accept or reject flagged documents.
  • The AI runs on-premise. A small open model runs in its own container next to Verity, with no connection to the outside. Documents and questions never go to OpenAI, Anthropic or any other AI provider. After the one-time model download, it works fully offline.
  • The AI only ever sees documents the person is allowed to see, and only the facts from the one document it's answering from.
  • A small model can make mistakes, so every AI answer is checked: each number in it must appear in the source document. If one doesn't, Verity shows the document's own words instead. Under every answer, the exact lines from the document are shown as quotes.
  • Uploads are limited to text files under 200 KB. Documents are displayed safely, so a document can't run code in the browser.
  • Repeated login attempts are slowed down. Session cookies can't be read by scripts. Protection against forged clicks is in place.
  • No passwords or keys in the code. We run the Aikido scan, fix what it finds, and submit screenshots from before and after.
